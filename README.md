# Locally Save

> Obsidian desktop plugin (interface in Chinese): syncs your vault to a **local folder copy** in
> seconds, and exports changes / a full copy as a **single transferable file** (`.lsave`) to carry
> on a USB drive or cloud folder. No network calls at all.

把 Obsidian 仓库同步到**本地磁盘上的一个文件夹副本**，几秒完事；再提供一个"同步包"，
把改动或整份副本装进单个文件，用 U 盘 / 网盘搬来搬去，在另一台机器上打开即可应用。

对标 Remotely Save 的用法，但走的是本地文件系统而不是网络 —— **完全不联网**。

## 安装

**手动安装**（当前没上架社区插件市场）：

1. 到 [Releases](https://github.com/Kflho/obsidian-locally-save/releases) 下载最新一版的
   `main.js`、`manifest.json`、`styles.css`
2. 放进 `<仓库>/.obsidian/plugins/locally-save/`（没有这个目录就新建）
3. 在 Obsidian 里 **设置 → 第三方插件 → 已安装插件** 里把它打开

插件是**桌面端专用**（`isDesktopOnly: true`）—— 同步目标是仓库之外的文件夹，
Obsidian 的 vault API 出不了库，只能用 Node 的文件系统。

从源码装也可以：`npm install && npm run build`，`deploy.mjs` 会顺手把产物同步到
`OBSIDIAN_PLUGIN_DIR`（默认取环境变量，没设就跳过）。

## 为什么

走网络的同步插件，几百 MB 的仓库来回传一次要等很久；而同一台机器上两个文件夹之间
复制 500MB 只需要几秒。日常备份、异地机器之间搬运，本地路径快得不是一个量级。

## 功能

### 本地同步

把仓库同步到任意本地文件夹（可以指向移动硬盘、网盘的同步目录、另一块盘）：

- **双向**：两边改动互相补齐；也可以选**仅上传**（副本只作备份）或**仅下载**
- **同步删除**：本地删的副本也删，反之亦然；可以关掉；关掉后之前删掉的文件会从另一边取回
- **删除前先备份**：删掉的文件挪进回收目录，而不是直接消失
  （副本那边在 `目标文件夹/.lsave/trash`，本地这边在 `仓库/.trash/locally-save`）
- **两边都改了怎么办**：默认留两份 —— **新的那份占原名**，输的那份挪进回收目录的
  `冲突` 文件夹（`仓库/.trash/locally-save/冲突/时间戳/原路径`），
  **不会留在原地**（留在原地的副本会跟着同步传到对面去、两边各滚一份）。
  也可以选"以本地为准"或"以副本为准"
- **排除规则**：写法同 `.gitignore`（`目录/`、`*.tmp`、`a/**/*.md`），
  默认排除配置目录（各台机器的插件与快捷键往往不同）
- **自动同步**：启动后一次 / 定时 / 保存后静置若干秒，三个开关默认都关着
- **预览**：`预览同步（不执行）` 先摊开"这次会干什么"，确认了再动手
- **状态栏**：同步 / 导出 / 应用进行中都显示进度，平时显示上次同步的结果。
  导出报的是"**已经打进包里几个文件 / 一共几个**"（就是个文件数，从 0 数到总数）
- **文件夹也一起同步**（含**空文件夹**）：对面没有的目录会建出来。删除同样传得过去，
  但要过基准检查 —— 只有"上次同步时两边都有过"的目录才会因为对面没了而跟着删，
  刚新建的绝不会被当成"对面删过它"
  - 删目录**只走 `rmdir`**：里面但凡还有东西就删不动，所以判断错了最坏也只是"没删掉"，
    不会连带删掉有内容的目录
  - **深的先删**：父子都要删时先删子目录，一轮就清干净（不然父目录被"非空"挡住，
    会出现"每次删掉一批、还剩一批"）
  - 目录里躺着**被排除规则挡住的文件**（`*.lsave`、`desktop.ini` 这类）时删不掉：
    插件会**如实告诉你哪几个删不掉、为什么**，而不是每轮都默默列一遍
  - 被删空 / 挪空的目录会顺手收拾掉；「删父目录」与「建新子目录」不会同时发生
    （对面删了 `A`、你这边刚加了 `A/B` 时，留 `A` 让新内容说了算，一轮到位）

### 同步包（`.lsave`）

把仓库打包成**单个文件**，拷到另一台机器上用插件打开：

- **完整副本**：整个仓库，到哪台机器都能整份恢复；也是更新包的**基准**
- **更新包**：自上次完整副本以来**累积**的全部改动（含一份删除清单）。
  对方永远只需要应用**最新那一个** —— 跳过中间几个也不会少内容，也不会留下冲突副本
  （它认得出"这是你以前发过的版本，不是我自己改的"）
- **打开即报告**：选包之后先算一遍再让你决定 —— 同步程度百分之多少、
  会新增/覆盖/跳过/冲突各几个、会不会删东西、走的是快速通道还是逐文件合并、
  中间有没有漏包。**打开包这一步不写任何文件**
- **文件与文件夹都报**：包里几个文件夹、本地几个、两边都有几个、要补建/删掉/留着各几个 ——
  只报文件的话，你永远不知道目录这边差多少
- **校验**：包尾部记着整段负载的 sha256，传输过程弄坏了会被拒绝（而不是写进仓库）
- **旧的更新包会被新的取代**：导出成功后 `changes` 目录里**只留最新那一个**
  （任何更新的更新包或更新的完整副本都包含旧包的全部内容，留着只是占地）。
  完整包**永远不删** —— 那是你的还原点。不想自动清就在设置里关掉
- **两种一起勾时，先导完整副本、后导更新包**：完整副本一写完，它自己就是最新的**基准**，
  这时的更新包按它算**必然是空的** —— 那就不写空包，只在结果里说一句
  （"更新包没有生成：刚导出的完整副本已经是当前仓库的完整样子"）。
  想要一个"小文件传出去"就**只勾更新包**，别同时勾完整副本
  （旧版本反过来先导更新包：先把上一个更新包清掉、再生成一个内容一模一样的，纯属白折腾）
- **包管理**：导出弹窗、导入弹窗、以及命令面板里的 `管理同步包…` 都会列出包文件夹里的所有包，
  而且**按类型分组**：更新包一组、完整副本一组、读不出头部的一组 —— **组内从新到老**，
  组标题吸顶，滚动时也知道自己在看哪一类。选中一行可以 **应用…** / **打开所在文件夹** /
  **复制路径** / **删除**；删除只是把包**挪进回收站**
  —— 默认布局下就是 **`目标文件夹/.lsave/bundles-trash/时间戳/`**（跟 `bundles` 平级，
  不会再套一层 `.lsave`），想反悔可以手动捞回来。
  列表**上方**那一行就是回收站：还剩几个包、占多大，还会把完整路径写出来 ——
  点「清空回收站」才是**真删**。
  读不出头部的 `.lsave` 也会列出来、单列一组 —— 看得见才删得掉
- **攒大了会提醒换基准**：更新包超过你设的上限（默认 200MB）时弹窗，三个选项 ——
  **重新导出完整副本** / **打开更新包文件夹**（去把包拷走）/ **跳过这次导出**。
  建议顺序是"**先把手上这个更新包传过去应用**（增量传得快）→ 再换基准"，
  因为换基准之后旧的更新包就没用了（会被清掉）。
  跳过之后提醒线按原上限整数倍往上抬（200 → 400 → 600MB），不会每轮同步都烦你
- **自动留包**：两个开关**各自独立**（默认都关）
  - **留更新包** —— 每次同步成功后把累积改动导成一个包。用的是同步刚扫完的结果，
    **几乎不额外花时间**；没有改动就不导。适合天天来回搬
  - **留完整包** —— 每次同步成功后导一份整个仓库。**每次都要把整个仓库重写一遍**，
    几百 MB 的库会明显变慢，只在"随时要给别人一份完整副本"时打开
  - 两个都开时**先留完整包、后留改动包**：完整包刚把整个仓库装走，改动包按它算必然是空的 ——
    那就不写空包，状态栏里说明一句（"改动包是空的（刚留的完整包已含全部内容），没生成"）
  - 更新包会随改动越攒越大（笔记型仓库通常几 MB 就到顶）；**导一次完整副本，累积就清零**
  - 第一次必须先导一次完整副本 —— 更新包要有基准才谈得上"累积"
- **包放在哪**：默认在**同步目标文件夹**的 `.lsave/bundles` 下 ——
  这个目录不参与同步，所以包不会被当成"副本新增的文件"传回仓库。
  完整包与改动包分别放在它的 `full` 与 `changes` 子目录里；
  设置里填了「同步包文件夹」就改用你指定的路径（同样会分这两个子目录）

### 三个左侧栏图标

插件在左侧栏放三个图标（**每一个都能在设置里单独关掉**，见「界面与交互」页）：

| 图标 | 点一下 |
|---|---|
| ⟳ 刷新类图标 | **立即同步到本地副本** |
| 📦 包裹类图标 | **导出同步包**（打开导出对话框） |
| 📂 开箱类图标 | **打开同步包并应用**（选中包 → 先看报告 → 再应用） |

跟命令面板里的 `立即同步` / `导出同步包…` / `打开同步包并应用…` 是同一套动作，
喜欢哪种入口用哪种。图标名是**运行时**从 Obsidian 的图标清单里挑的
（`IconName` 在类型上就是 `string`，写错了只会静默显示成空白方块，所以不能猜）。

包攒多了想清一清、或者只是想看看某个包放在哪个目录：命令面板里还有一条
**`管理同步包…`**（没有左侧栏图标，需要时从命令面板叫出来）。

设置面板的「本地同步」页里也有对应的按钮，找不到命令面板时从那儿点。

同步包相关的设置都在设置面板的**「本地同步」页**里（它本来就是本地同步的搬运方式）。

## 怎么用同步包（跨机器搬运）

假设要把 A 机（笔记本）的仓库搬到 B 机（台式机），或者让两台机器来回同步。

### 第一次：A → B，用**完整副本**

1. **A 机**：设置 → Locally Save → 本地同步 → 滚到「同步包：手动导出」→ 点 **导出同步包…**
   （或者 `Ctrl+P` 输入 `导出同步包`）
   - 勾上 **导出完整副本**（第一次必须导完整副本：更新包要以它为基准）
   - 「导出更新包」与「导出完整副本」是**两个独立勾选**，可以都要。
     两个都勾时**先导完整副本、后导更新包** —— 完整副本刚把整个仓库装走，这时的更新包
     必然是空的，所以**不会生成空包**，结果里会写一句为什么
     （想要"一个小文件传出去"，就只勾更新包）
   - 「同步包文件夹」留空就跟着目标文件夹走，对话框里会写明 **会写到：** 哪个目录；
     也可以填个方便拷走的地方（比如 U 盘）
   - 底下还列着这个文件夹里**已有的包**（更新包一组、完整副本一组，组内从新到老）：
     选中一行就能 **应用… / 打开所在文件夹 / 复制路径 / 删除**
2. 把生成的 `.lsave` 文件拷到 B 机（U 盘、网盘、聊天软件，怎么拷都行）
3. **B 机**：**把那个 `.lsave` 直接拖到 Obsidian 窗口上**（会自动打开对话框并填好路径），
   或者 设置 → Locally Save → 本地同步 →「同步包：应用」→ 点 **打开同步包并应用…**
   - 从列表里选（按类型分组，更新包与完整副本各一组、组内从新到老），也可以直接粘完整路径
   - **先看报告**：同步程度、新增/覆盖/冲突/删除各几个、走哪条通道、有没有漏包
   - 确认无误，再点 **应用**

> 拖放只拦 `.lsave`，别的文件一概放行 —— 往笔记里拖图片、拖别的附件照旧。
> 不想要这个行为可以在设置里关掉（「拖入 .lsave 即打开应用对话框」）。

### 之后：日常来回搬，用**仅改动**

1. A 机同步一次 —— 如果开了「同步后自动留改动包」，包已经躺在 `changes` 目录里了；没开就手动导一次（选「仅改动」）
2. 拷到 B 机 → 打开并应用。B 机没动过的话，报告会显示同步程度 100%

### 应用时按什么规则处理

**与本地副本同步同一套规则** —— 不再有"三个模式"那种死板的东西：

| 情况 | 处理 |
|---|---|
| 本地没动过、包里有 | 按包写入 |
| 两边都改过 | 按设置里的「两边都改了怎么办」：默认**留两份 —— 新的那份占原名**，输的那份挪进回收目录的 `冲突` 文件夹 |
| 包里有、本地那份只是旧副本 | 直接覆盖（不算冲突） |
| 本地有、包里没有、**基准里也有** | 对方删过它 → 按「同步删除」处理（关掉就取回来） |
| 本地有、包里没有、**基准里也没有** | 我独有的文件，对方从没见过 → **一律保留** |
| 对方改名 / 挪了位置 | 本地跟着改名，不重传内容 |
| 空文件夹 | 包里记着的空目录会**补建**出来；包里没有的本地空目录，默认档只删"对方删过的" |
| 本地是文件夹、包里是同名文件 | 默认档**如实报失败、不动那个文件夹**；强制档才把它挪进回收目录腾地方 |

两条要紧的语义差别（踩过坑，都写进测试了）：

- **「本地有、包里没有」= 对方删过它**，这条**只对完整副本成立**。完整副本是"完整清单"，
  而更新包只装自完整副本以来变过的文件 —— "没提到"什么也不代表。
  所以更新包**只按它点名的删除清单删**，其余文件一律不动
- **更新包只开放默认档**：拿更新包做"清老的/强制应用"会把仓库里其余文件全当成"该删"。
  界面上那两个选项会灰掉，引擎层也会兜底降级（并在报告里说明）

「应用方式」有三档，一条轴：有多"以包为准"：

| 档 | 干什么 | 什么时候用 |
|---|---|---|
| 默认（所有都保留） | 只应用包里有的；本地多出来的文件一个不动；两边都改过留冲突副本 | 日常 |
| 清老的 | 额外删掉本地那些"比包旧"的多余文件（比包新的不动 —— 那多半是你刚写的） | 对面整理过仓库 |
| 强制应用（完全一致） | 让仓库与包**完全一样**：本地改动一律被覆盖、多余文件全删、连"本机新建的空文件夹"也删 | 对面大删大改过，想让这台机器跟包一模一样。**会额外确认一次** |

强制两档**必然先备份**（回收目录忽略设置强制打开）：关掉回收 + 强制 = 不可恢复的批量删除，
这个组合不给走。对话框里可以**临时覆盖**冲突与删除这两条（默认「跟随设置」）。

判定基准是"我上次应用/导出之后的样子"，所以"对方删的"和"我独有的"分得清清楚楚 ——
不需要用户先选立场。

### 双击 `.lsave` 直接用 Obsidian 打开

设置 → Locally Save → 本地同步 → 「同步包：用 Obsidian 直接打开」→ **设置关联**。
之后双击 `.lsave` 就会用 Obsidian 打开并**直接弹出应用对话框**。

为什么不能简单"用 Obsidian 打开"：把 `.lsave` 关联到 `Obsidian.exe "%1"` 是**通不了**的 ——
Obsidian 收到一个陌生路径只会当成未知文件，压根到不了插件。能到插件的通路只有 **URI 协议**，
所以关联要指向 `obsidian://locally-save?vault=<仓库名>&bundle=%1`（`%1` 由系统换成被双击的路径）。

两个坑（都踩过，写在代码注释里了）：

- **`vault=` 不能省**：插件属于某个 vault，Obsidian 得知道把 URI 交给哪个。
  少了它会直接弹 **`Vault not found. Unable to find a vault for the URL`**，压根到不了插件。
  链接里的仓库名就是**当前打开的仓库**，换 vault 或改过文件夹名后重新点一次「设置关联」即可
- **参数名不能叫 `path`**：Obsidian 对 URI 里的 `path` 有特殊处理（[官方文档](https://obsidian.md/help/uri)：
  "path 会覆盖 vault 与 file，并让应用去搜索哪个 vault 包含这个路径"）。
  我们的包在仓库外、不属于任何 vault —— 于是它找不到 vault，报同一个错。所以用的是自定义参数名 `bundle`

- 只写**当前用户**注册表（`HKCU\Software\Classes`），**不需要管理员权限**；
  点"设置关联"前会把要跑的命令**逐条列出来**
- 会覆盖你现有的 `.lsave` 关联；不想用了在同一处点 **解除关联**
- 链接形式也可以手工用（路径要 URL 编码）：
  `obsidian://locally-save?vault=我的仓库&bundle=D%3A%5C%E4%BC%A0%E8%BE%93%5Ca.lsave`
- 不带路径也行：`obsidian://locally-save?vault=我的仓库` 就是"打开应用对话框，让我自己选"
- **这台机器上双击没用？** 关联是**每台机器各自设置**的（注册表在本机），
  换机器后要在那台机器上重新点一次「设置关联」；在此之前用拖放或对话框选文件一样能用

### `.lsave` 不是 Obsidian 能打开的格式

同步包是插件自己的容器格式。**不要**用"用 Obsidian 打开"去双击它（除非你按上面设过关联）——
那样只会被当成一个未知文件塞进仓库。正确用法是**把包拖到 Obsidian 窗口上**，
或者用插件里的对话框选它。

- 插件读包**只看绝对路径**，跟你系统里 `.lsave` 关联到哪个程序**完全无关**
- 默认排除规则里有 `*.lsave`：万一包被拖进了仓库，它也不会跟着同步出去
  （确实想让包参与同步，把设置里「不同步的文件」中那行删掉即可）

### 应用完，本地副本要不要跟上

对话框里有一项 **「应用后顺便同步到本地副本」**（填了目标文件夹时默认开着）：
应用完再跑一次正常同步，把这次的改动推到副本。不这么做的话，备份会在应用完包之后
悄悄落后一截 —— 你以为它是新的，其实不是。

顺序上有个讲究：**包里删掉的文件，会先从副本里也清掉、再把基准划掉，然后才同步**。
否则常规同步会把它们当成"本地缺了、该从副本取回"，刚删掉的文件又长回仓库
（「同步删除」关着时必然如此）。

### 几个要点

- **打开包那一步是只读的**：随便点、随便看，不会动你的文件；只有点「应用」才写盘
- **包里要求删、本地改过的文件不删**（删除必须过基准检查，没有例外）
- 提示「**漏了包**」不用慌：插件会降级成逐文件合并 —— 能安全写的照写，本地也改过的留冲突副本。
  想彻底对齐，让对方导一份完整副本
- 自动留包的两个开关**各自独立**：只开「改动包」最省（几十 KB 到几 MB）；
  「完整包」每次都要重写整个仓库，几百 MB 的库会明显变慢。
  两个都开时**先留完整包** —— 改动包按它算必然是空的，那就不留（状态栏里会说明一句）
- 包丢了、传坏了都不影响仓库：**导出是只读的**，包损坏会在应用前被校验拦下

设置面板里也有一个 **「看说明」** 按钮，写的就是上面这套流程。

## 设置面板

按"用户要干什么"分成四页（1.13+ 是可折叠的分页，旧版本平铺成小节）：

| 页 | 里面有什么 |
|---|---|
| **通用** | 总开关、日志级别、启动提示与文案 |
| **本地同步** | 同步目标 · 删除与冲突 · 同步包（自动留包 / 手动导出 / 应用 / 用 Obsidian 直接打开） |
| **自动同步** | 启动后一次 · 定时（间隔）· 保存后静置（秒）· 状态栏显示 |
| **界面与交互** | 左侧栏三个图标 · 状态栏 |

几个容易忽略但很有用的：

- **不同步的文件**：写法同 `.gitignore`（`目录/`、`*.tmp`、`a/**/*.md`），
  默认排除配置目录、`.lsave/`、`*.lsave` 与系统垃圾文件
- **删除前先备份**：关掉之后删除就是直接删（强制档下这一项会被强制打开）
- **打开包时最大化窗口**（默认开）：双击 `.lsave` / 拖进来时把 **Obsidian 窗口本身**顶到最大
  并叫到前台 —— 应用一个包要跑几秒，窗口小或在后面时看着就像卡死了
- **应用前校验完整性**：把整个包读一遍算校验和，确认传输没把文件弄坏（大包会多花几秒）
- **更新包超过多大就提醒换基准**：认 `200MB` / `500KB` / `1GB`，不带单位按 MB 算；
  留空＝默认 200MB，**填 0 ＝ 不提醒**
- **导出后清掉被取代的旧更新包**（默认开）：`changes` 里只留最新那一个

## 为什么不让"包"直接当同步目标

看上去更统一（本地就一个文件），但性能上不划算。`.lsave` 的头部记的是每个文件在负载里的
**绝对偏移**，任何一个文件大小一变，后面的偏移全要挪 —— 除非把格式改成"只能往后追加 + 索引放尾部"，
否则**每次同步都得整包重写**：

| 场景（500MB 库 / 1 万文件 / SSD） | 文件夹副本 | 单包（整体重写） | 单包（追加式改造后） |
|---|---|---|---|
| 改一个 10KB 笔记后同步 | 只复制 10KB **≈0.2 秒** | 重写 500MB **≈2–5 秒** | 追加 10KB + 重写索引 **≈0.3 秒** |
| 比对扫描 | 两侧各 1 万次 stat | 索引直接给出（更快） | 同左 |
| 磁盘占用 | 1× | 1× | 1× + 垃圾，需定期压实 |
| 谁能打开 | 任何程序都能直接读 | 只有本插件 | 只有本插件 |
| 损坏的后果 | 坏一个文件 | 整包校验失败 | 整包/索引损坏 |

文件夹副本的增量是**内核级**的（`copyFile` 只搬改动的那几个字节），包格式的增量得我们
自己在 JS 里维护索引与偏移。所以这里的分工是：**文件夹副本当同步目标**（快、透明、坏只坏一个），
**包当传输格式**（单文件、带校验、带世代）。

## 它是怎么判断的

同步的核心是**三方对比**：以上次同步后的样子为基准，分别看本地和副本现在什么样。

```
   上次同步记下的状态（基准）
        ↙            ↘
  本地现在的样子    副本现在的样子
```

- 只有跟基准不一样的那一侧才算"改过"；一边没了、另一边没动 → 那就是删除
- 两边都动过 → 按冲突策略处理，默认留两份，绝不静默覆盖
- **移动会单独认**：改名/挪目录本质是"删一个 + 加一个"，真按两步做的话，
  关了删除传播时旧文件会被拉回来、两边各留一份。所以比对阶段会按
  「大小 + 修改时间完全一致」把「新增」与「对侧删除」配对，配对成功就在对侧直接改名，内容不重传
- 复制之后会把修改时间对齐到源文件 —— 不对齐的话每轮都会误判成"改过"，反复重传

## 同步包的累积与世代

更新包是**以完整副本为基准累积**的，这是整套设计里最关键的一条：

```
完整副本 F0  ──►  更新包 C1（自 F0 以来）──►  更新包 C2（自 F0 以来，含 C1 的内容）──► …
                      │                                    │
                   对方应用 F0 之后，应用 C1 就是最新的；直接应用 C2 也是最新的
```

所以：**永远只需要应用最新的那一个**，不用担心顺序、不用担心漏包。代价是包会越滚越大，
**导一次完整副本就清零** —— 这不是可选项，而是这套方案的节制阀。

每个文件除了新内容，还带两样东西，用来判断"本地那份能不能直接覆盖"：

| 字段 | 含义 | 什么时候对上 |
|---|---|---|
| `base` | 我**上次导出**时这个文件的样子 | 对方每次都跟着应用（最常见） |
| `history` | 自完整副本以来它经历过的中间版本 | 对方跳过了一两个包 |

两个都不对 → 那才是**真的本地改动** → 留冲突副本，两份都在。

删除一视同仁：包里要求删、但本地改过的文件**不删**（只登记为"保留"）。
只有当本地仍停在 base 或某个中间版本上时才真删 —— 这是唯一不可逆的动作，宁可留着。

对方世代**低于**包的基准世代（= 没应用过那个完整副本）时会明确提示：
"你还没应用这个包所基于的完整副本，请先要一份完整副本" —— 而不是默默应用一半。

## 已知边界

- **只支持桌面端**（`isDesktopOnly: true`）：同步目标是仓库之外的文件夹，
  Obsidian 的 vault API 出不了库，只能用 Node 的文件系统
- 比对用「大小 + 修改时间」，修改时间带 2 秒容差（FAT/exFAT 只精确到 2 秒）。
  代价是：**同一个文件在 2 秒内被改成同样长度**，这一轮可能看不出来，下一轮才会发现
- 在**副本**里改名，不会更新仓库笔记里指向它的链接（Obsidian 只跟踪应用内的改名）。
  在仓库里改名（正常用法）不受影响
- **删不掉的空目录**：目录里只有被排除规则挡住的东西时（`*.lsave`、`desktop.ini`、`.DS_Store`…），
  插件看不见它们、`rmdir` 也就删不动。这时会**明确报出来**（"里面还有东西，只删空的"），
  而不是反复尝试
- **打开更新包文件夹**依赖系统文件管理器：优先走 Electron 的 `shell.openPath`，
  拿不到就退回 Obsidian 自带的"用默认程序打开"，都不行时弹一条含路径的通知让你手动复制
- 「打开包时最大化窗口」走社区通用的 `@electron/remote`；万一某个版本拿不到，
  会退回 `window.moveTo/resizeTo`，再不行就只把窗口叫到前台（不报错）
- 状态文件在 `.obsidian/plugins/locally-save/sync-state.json`，记录每个目标的基准、
  世代、目录基准与内容指纹缓存。删掉它等于"当作第一次同步"，不会动仓库里的文件
  （老状态文件里没有"目录基准"这一项：升级后第一轮谁都不删，第二轮起才正常）

## 隐私

**这个插件不发起任何网络请求。** 没有遥测，没有账号，不上传任何东西。
它只做两件事：读你指定的本地文件夹、按上面的规则复制或删除文件。

## 开发

```bash
npm install
npm run dev      # 监听改动，打包完自动同步到 vault 的插件目录
npm run build    # 类型检查 + 生产打包
npm test         # 556 项检查（比对矩阵 / 排除规则 / 端到端同步 / 同步包 / 设置面板 / 装配）
npm run lint
```

改完在 Obsidian 里 **设置 → 第三方插件** 重新加载即可。

### 发版

```bash
npm version 0.2.0        # 同步 manifest.json 与 versions.json，并打好同名 tag（不带 v 前缀）
git push origin main --follow-tags
```

CI（`.github/workflows/release.yml`）会在 tag 推上去之后跑测试与构建，
校验 **tag 与 `manifest.json` 的 version 一致**，然后创建 Release 并附上
`main.js` / `manifest.json` / `styles.css`。版本号忘了改就打 tag 会被直接拦下。
