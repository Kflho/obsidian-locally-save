# 换基准之后那一段：差量包与整理清理（0.18）

> 用户 2026-11-04 的原话："我本地导了一个新的完整包，希望加个功能，对面能根据更新包
> 同步到完整包，清理旧包，使得两边都在新的完整包基础上更新，然后清理旧的完整包。"
>
> 现状（真机）：本机 `Kflho_thinkbook` 基准是第 **961** 代那份完整副本上（541 MB），
> 另一台 `KahoTAT` 还基准是第 **320** 代（内容到第 651 代）。货架只推 `changes/`，
> `full/` 被排除 —— 新的完整副本它**根本拿不到**，而本机之后的更新包是"从 961 算起"的，
> 它收下会被判「基准对不上」。旧的 320 完整副本（526 MB）还躺在本机 `full/` 里。

## 1. 缺口在哪

引擎里**已经有**这条路：差量包（`header.targetFullBundle`，端点都是完整副本）应用完
基准会前进到终点那份（`apply.ts` 的 `landedOnBaseline`），接收方**不需要手里有新的完整副本**。
缺的是"用起来"的那三步：

| 缺口 | 现场表现 |
|---|---|
| 手动导出完整副本时**不导差量包** | 只有"自动留完整包"那条路会顺手导（`ui/actions.ts`）；而自动留完整包默认关着，用户是手动导的 |
| **没有"按对面报的基准逐个导"的入口** | `exportRebaselineDiff` 只知道"导出前我站的旧基准"，多台机器停在不同旧基准上时算不过来 |
| **旧完整副本从来没被清过** | `removeSupersededChanges` 明文写着"完整包一律不碰（那是你的还原点）" |

## 2. 做了什么

### 2.1 `bundle/rebaseline.ts`：按每台电脑各自报的基准算差量包

计划（**只读**）：`planRebaselineDiffs(baseDir, state, peers)` —— 我用哪一份
（`state.bundle.fullHash`）、每台用哪一份（`.lsave-peers/*.json` 的 `baselineHash`），
逐台给一个结论：

| 结论 | 意思 | 处置 |
|---|---|---|
| `ready` | 它站的旧完整副本在本机、终点是我这份 | 导一份差量包 |
| `exists` | `changes/` 里已经有一份同样的（起点代 ＋ 终点代 ＋ 终点状态编号） | 不重复导 |
| `same` | 它已经站到我这份上了 | 什么都不做 |
| `ahead` | 它站的比我这份新 | 该收它的，方向反了 |
| `diverged` | 同一代、不是同一份（两条线各立过基准） | 不做：差量包会把它整片换成我这份 |
| `missing` | 本机没有它站的那份完整副本 | 做不出来，把完整副本整份拷过去 |
| `no-baseline` | 它还没站上任何完整副本 | 先让它应用一份完整副本 |
| `too-big` | 预计要搬的字节超过 80 MB | **不写包**：写入会进 `changes/`，之后每轮 `git add` 都带着它失败，把货架搞停 |
| `no-target` | 我站的这份完整副本不在本机磁盘上（应用差量包变成某个基准之后就是这样） | 先把那份拷进来 |

执行：`exportRebaselineDiffs(options, plan)` 只导 `ready` 那几条，一条失败不影响其余；
本机什么都不推进（差量包那一趟是 `frozen`：世代、基准、状态编号都不动）。

入口三处，共用同一套判断：
- 命令 `export-rebaseline-diff`「导出换基准的差量包…」（新增 ID，老 ID 一个没动）；
- 「管理同步包」窗口里「换基准之后」那一行的「导出差量包…」；
- **导出完整副本之后顺手来一下**（手动导出窗与自动留包两条路都接了）—— 一台都没上报就什么都不做。

### 2.2 收包侧：差量包一律按严格镜像应用

`incoming.ts` 的 `handleIncoming`：头部 `targetFullBundle` 的包，「双向」那边默认是
`normal + keep-both`（三方合并），这一档会坏在**新基准令牌**上：

```
nextFullFiles = 应用前的清单 ＋ 真的写成了一致的条目 − 点名删除
```

合并档留下本机那一半，可"冲突里赢的是本机那一版"的路径**不在**"写成了一致的条目"里，
它的记录就按**祖先那一版**记进新基准 —— 落出来的 `fullHash` 既不等于旧基准、
也不等于包里报的 `targetBaselineHash`（实测：`test/rebaseline.test.ts` 第 5 组末尾的对照，
落成 `ed58f4b9…` 而包里报 `67886f31…`）。之后对面按新基准导的更新包，这台机器一律判不上，
**永远卡住**。

所以改成镜像：结果是确定的 ＝ 包里那一点，写入指纹正好等于头部报的那个。
代价是本机被覆盖 / 多出来的文件进回收目录（严格档必然备份，`.trash/locally-save/`）。
「双向」方向仍会先问一句，只有开了无人值守那条路才直接落。

> 走过一次弯路，记下来：一开始以为"合并档会把令牌弄脏"是错的、想撤掉这条强制，
> 结果发现测试里那条对照跑的是**已经被强制镜像**的路径（结论当然一致）。
> 把强制撤掉重跑才看出真现象。**判据必须用没被改写的那条路去验。**

### 2.3 清理

分两种，判据同一条：**它的起点已经没人站了**（应用一份包要求接收方停在它起点那份上）。

- **更新包 / 差量包：自动**（`removeSupersededChanges`，每次导出之后跑）——移到**回收站**，
  不是删（那一边"被新包完全覆盖"才删）。三道闸：货架上没有任何别的电脑上报过 → 不动；
  有一台还报着这个起点 → 不动；旧包没记指纹 → 不动。报告里记在 `ExportOutcome.retired`，
  界面写"N 个包的起点已经没人站了，移到了回收站"。
- **完整副本：永远手动**（`bundle/stale.ts` 的 `planStaleFullBundles`）。完整副本是还原点，
  自动删它没有正当理由。列出来的条件：不是我站的这份、没有任何一台电脑报的 `baselineHash`
  等于它、世代不比我这份新。入口在「管理同步包」→「清理旧完整副本…」，
  先摊开（哪几份、多大、谁已经不在上面了），确认了才移到回收站。

### 2.4 收下差量包的那台，自己也要留住这个基准（0.18.1）

用户追加一条："对面接收后也要导出一个完整包，保证两边完整包相同，然后才继续更新，这样最稳。"

应用差量包之后 `fullFile` 是空的（手里只有更新包）。后果不算致命但都会踩到：
`findBaselineBundle` 按名字找不到它 → 「恢复本机误改」/「强制回退」只能报"把那份包放回来"；
给第三台机器导差量包时，终点那份完整副本不在本机也做不出来。

写入：`planBaselineCopy(state, inventory)`（只读）＋ `ensureLocalBaselineBundle`，
接在**应用成功之后**（自动收包那条路 + 手动应用对话框收尾），所以点一次「立即同步」就全做完。

**关键是那道指纹核对**：`listingHashOfFiles(inventory.files)` 必须等于 `fullHash` 才补 ——
同一算法就是 `exportBundle` 里 `freshBaseline` 用的那个。不等说明磁盘上这份**不是**大家站的那一点
（典型是另一个文件系统的 mtime 精度），补出来的会是**另一个基准**，两边从此对不上；
那种情况宁可不补、如实说，也别让两边悄悄分岔。补的时候世代不动（`moved` 看内容编号）、
`fullHash` 不变，只是多一个包文件、`fullFile` 有了名字。

## 3. 没做 / 边界
- **自动收包那条路不 park**：镜像把本机改动送进回收目录，不额外存一份回传包
  （那会在后台凭空写包）。要"动手前先存一份"，走「打开同步包并应用…」——那里本来就 park。
- **差量包超过 80 MB 就只报不导**：`gitMaxFileMb` 这个设置从来没实现过，这里按 GitHub
  单文件 100 MB 的硬限制卡了一道；真要传大包还是整份拷完整副本。
- **`ahead` / `diverged` 不自动处理**：两条线各立过基准时，谁吞谁得人来定。

## 4. 守护

`test/rebaseline.test.ts`（80 项）：计划各档位（ready / exists / same / missing /
no-baseline / too-big）、导出后的头部坐标（起点代、终点代、两端指纹）、
**对面用差量包写入之后 `fullHash === 包里报的那个`**、两台内容与状态编号一致、
本地独有的文件没消失、清理的三种前提（没上报 / 还停在上面 / 没人站）、
差量包在没人站旧基准之后自动退休且在有人站时留着、合并档与收包那条路的对照、
**收下之后补一份完整副本**（核对指纹 / 改动时间就不补 / 补出来的指纹与世代 / 补完照样导得出更新包）。
`test/commands.test.ts` 同步了命令 ID 表。
