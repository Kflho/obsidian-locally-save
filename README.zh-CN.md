# Locally Save 中文说明

> English documentation: [README.md](README.md)

## 1. 概述

Locally Save 是一款 Obsidian 桌面端插件，用于在离线环境下迁移仓库。插件将整个仓库或自某份完整备份以来发生变更的部分封装为单个 `.lsave` 文件，用户可通过移动存储设备、网盘或即时通信工具将该文件传输至另一台计算机并应用。

插件不依赖网络服务，不要求账号，不执行后台同步。其功能范围限于离线迁移与还原点管理。

## 2. 适用场景与边界

适用场景：

- 更换计算机或重装操作系统：应用一份完整备份即可恢复笔记与目录结构；
- 两台计算机轮流使用：日常仅传输发生变更的部分，文件体量通常为数十 KB 至数 MB；
- 建立还原点：将当前仓库完整导出，发生误改后可应用该备份恢复。

不适用场景：

- 多台计算机通过共享目录持续保持自动一致。该需求应由 Remotely Save 配合 WebDAV 或坚果云等方案实现；
- 移动端使用。本插件依赖桌面端文件系统，仅支持桌面端。

## 3. 安装

### 3.1 从社区插件市场安装

在 Obsidian「设置 → 第三方插件 → 浏览」中搜索 Locally Save，安装并启用。

### 3.2 手动安装

1. 从 [Releases](https://github.com/Kflho/obsidian-locally-save/releases) 下载 `main.js`、`manifest.json` 与 `styles.css`；
2. 将上述文件放入 `<仓库>/.obsidian/plugins/locally-save/`；
3. 重启 Obsidian，在「设置 → 第三方插件」中启用 Locally Save。

## 4. 核心概念

| 概念 | 定义 |
| --- | --- |
| 完整备份 | 将整个仓库写入一个 `.lsave` 文件。完整备份同时作为基准与还原点 |
| 更新包 | 自某份完整备份起至另一状态之间的差量，仅包含该区间内发生变更的文件 |
| 差分更新包 | 两份完整备份之间的差量，用于更换基准后让其他计算机跟上新基准 |
| 同步包 | 承载上述内容的 `.lsave` 文件 |
| 基准 | 本机当前依据的完整备份。应用或导出完整备份后确定，更新包不改变基准 |
| 版本号 | 仓库内容的版本编号，内容每变更一次递增 |
| 内容校验值 | 根据文件内容计算出的校验值，用于判断两台计算机的内容是否一致 |
| 远程仓库 | 存放同步包的 Git 仓库，推送与拉取均通过该仓库完成 |
| 接收文件夹 | 同步包文件夹中用于接收对方同步包的目录 |

关键规则：只有完整备份会推进基准；更新包在同一基准上累积。更新包体量增大后，应导出一份新的完整备份并更换基准。

## 5. 首次使用

1. 设置同步包文件夹。在「设置 → Locally Save → 同步包」中填写一个位于仓库之外的目录。该项为必填项；未填写时，导出与应用按钮不可用。
2. 在第一台计算机上导出完整备份。选择命令「导出同步包…」，勾选「完整备份」后执行导出。
3. 在第二台计算机上应用该同步包。将 `.lsave` 文件复制至第二台计算机，拖入 Obsidian 窗口，核对应用报告后执行应用。

完成上述步骤后，两台计算机的内容一致，基准为同一份完整备份。

## 6. 日常同步

日常同步仅传输发生变更的部分：

1. 在修改过内容的一台计算机上选择「导出同步包…」，导出更新包；
2. 将更新包传输至另一台计算机；
3. 在另一台计算机上选择「打开同步包并应用…」，核对报告后应用。

应用前应先查看报告。报告列出将写入、删除与恢复的文件数量，以及是否与对方内容一致。应用完成后，删除的文件与本机误改的文件均移入回收目录，可在需要时恢复。

### 6.1 冲突处理

若两台计算机修改了同一文件，插件保留修改时间较新的版本于原路径，另一版本移入回收目录的「冲突」目录。插件不执行行内合并；如需保留双方改动，应从回收目录取回另一版本并手动合并。

### 6.2 应用与校验

完整备份按严格镜像应用：应用后仓库内容与包内容完全一致。更新包要求包的起点与本机基准一致；不一致时插件拒绝应用并说明原因。应用前插件计算并核对内容校验值，以确认传输过程未损坏文件。

## 7. Git 传输（可选）

启用 Git 传输后，同步包文件夹可接入一个 Git 远程仓库，通过推送与拉取传输同步包。完整备份体量较大，不通过 Git 传输。

### 7.1 接入远程仓库

在「设置 → Locally Save → Git」中填写远程地址（HTTPS 或 SSH），选择方向并测试连通性。首次接入时，插件将同步包文件夹初始化为 Git 仓库并连接远程仓库。

### 7.2 方向

| 方向 | 行为 |
| --- | --- |
| 仅发送 | 不读取接收文件夹，仅导出并推送 |
| 仅接收 | 仅拉取并应用，不导出 |
| 双向 | 导出、推送、拉取并应用；应用前按设置决定是否确认 |

方向是硬性边界。接收文件夹仅用于存放对方发送的同步包，本机不会读取自身的接收文件夹。

### 7.3 同步包文件夹位于已有仓库

同步包文件夹可以是某个私有仓库的子目录。插件仅提交与同步包相关的改动，不修改该仓库的其他文件，也不修改远程地址。拉取仅执行限定范围的对齐：能够快进时快进；不能快进时，仅当本地未推送的提交全部位于同步包目录内，才执行自动变基。

### 7.4 更换基准

更换基准后，仍使用旧完整备份的计算机通过差分更新包跟上新基准。差分更新包按每台计算机上报的基准生成，应用时按严格镜像执行。接收差分更新包后，该计算机应补一份新基准的完整备份，以便与其他计算机共用同一基准。

## 8. 自动功能与通知

### 8.1 自动导出

自动导出默认关闭，可在「设置 → Locally Save → 自动导出」中配置以下触发时机：

- Obsidian 启动后导出一次；
- 按固定时间间隔导出；
- 笔记保存后延迟导出。

### 8.2 自动接收

未启用 Git 时，由「自动应用收到的更新包」开关决定是否自动应用。自动应用仅处理不会删除文件、也不会覆盖本机改动的更新包。启用 Git 后，由方向决定接收行为：仅接收与双向模式可按设置自动应用，仅发送模式不接收。

### 8.3 通知

通知仅显示两类内容：当前状态与需要用户执行的操作。

- 需要通知：完整备份需要手动应用、包起点不一致、应用失败、设置不完整、需要确认，以及自动接收删除了本机文件、恢复了本机误改或执行了强制回退；
- 不通知：例行的后台同步、自动导出成功、自动接收仅写入新文件。上述结果记录于状态栏、悬停详情、更新记录与日志；
- 一次接收多份同步包时，应用结果合并为一条通知；未能自动应用的同步包按「完整备份」「更新包」「失败」分类合并，并给出首个原因。

### 8.4 状态栏与图标

状态栏显示上次同步结果、当前内容校验值与当前进度。左侧栏提供三个图标：立即同步、导出同步包、打开同步包并应用，可在设置中分别关闭。

## 9. 数据安全与恢复

- 应用前，插件将本机这一半内容保存为一个同步包（「仅接收」方向除外），以便恢复；
- 删除或覆盖的文件移入 `<仓库>/.trash/locally-save/` 回收目录，不直接删除；
- 应用完整备份前可先校验包完整性；传输损坏的包不会被应用；
- 所有会修改文件的自动功能默认关闭，需用户显式启用。

## 10. 同步包管理与清理

- 「管理同步包…」可查看、应用或删除已有同步包；
- 可合并相邻的更新包，合并后的包起点为段首完整备份，目标为段末版本；
- 清理规则：更新包或差分更新包的起点已无任何计算机使用时，自动移入回收站；完整备份为还原点，永不自动清理，需手动删除。

## 11. 设置

设置分为以下页面：

| 页面 | 内容 |
| --- | --- |
| 同步包 | 同步包文件夹、导出与应用、包管理 |
| 自动导出 | 自动导出的触发时机与导出类型 |
| Git | 远程地址、方向、连通性、SSH 接入 |
| 通用 | 插件开关、日志级别、左侧栏图标、状态栏 |
| 高级 | 不进包的文件、导出起点与终点、自动应用、完整性校验、拖放行为 |

## 12. 常见问题与限制

- 同步包被拒收：包起点与本机基准不一致，或包目标版本早于本机版本。请核对报告中的起点信息；
- 包应用后版本未变化：应用未完全落盘，可能有文件写入失败或目录无法删除。插件不会在此情况下更换基准；
- 大仓库性能：插件按元数据扫描，数百 MB 的仓库可正常使用；文件数量达到数万时，扫描耗时增加；
- 移动端不支持：插件读写仓库之外的文件，依赖桌面端文件系统；
- `.lsave` 不是 Obsidian 可直接打开的格式。双击打开需先在设置中建立文件关联。

## 13. 隐私

不开 Git 传输时，插件不发起任何网络请求，不包含遥测，不上传任何内容。启用 Git 后，插件仅调用本机安装的 `git` 与用户指定的远程仓库通信，凭据由系统 Git 管理。

插件访问的范围限于：用户指定的同步包文件夹、仓库本身，以及仓库内的 `.trash/locally-save` 回收目录。
