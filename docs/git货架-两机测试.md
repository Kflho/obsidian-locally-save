# Git 货架 —— 两台电脑测试（0.15.0）

> 这一版插件里已经有「Git 远程」了。用户面前的主按钮是**左侧栏第一个图标「立即同步」**：
> 它会导出包、和远程推拉、把拉下来的安全更新应用掉。定时那套也还在。
> **不用再手敲 git 命令**；方向不对、两边都改过时，插件会停下来让你选。

**第一次别拿真库试**：两台机器都先用一个空仓库 / 备份过的库。

---

## 0. 两台机器各准备一次

1. **插件 0.15.0**：把 `main.js`、`manifest.json`、`styles.css` 放进
   `<仓库>/.obsidian/plugins/locally-save/`，重载 Obsidian。
   （本机 `npm run build` 会自动同步到插件目录；另一台机器把这三个文件拷过去。）
2. **Git**：装 Git for Windows，`git --version` 能出东西（插件里「测试连通性」也会替你查）。
3. **同步包文件夹**（两台各填各的，必须在库**外面**，比如 `D:\LocallySaveBundles`）：
   设置 → Locally Save → 同步包 →「同步包文件夹」。
4. **Git 远程**：设置 → Git 远程：
   - 打开「启用 git 传输」；
   - 远程地址填 `git@github.com:Kflho/obsidian-lsave-shelf-test.git`；
   - 分支 `main`；方向 **双向**；多久拉一次 **5 分钟**。
5. **先测连通性**：点「测试连通性」。它会当场告诉你：
   - `git：…`（装没装）；
   - `接入状态：…`；
   - `连通性：正常 / 失败 —— 原因`。
   失败时按窗口里那句下一步做（多半是 SSH 密钥还没加到 GitHub）。
6. **SSH 密钥**（报 `Permission denied (publickey)` 时）：
   点「SSH 接入…」——
   - 没有密钥：点「生成」（ed25519、无口令）；
   - 点「复制」把公钥贴到 GitHub → Settings → SSH and GPG keys → New SSH key；
     机器上登录过 `gh` 的话，可以直接点「用 GitHub CLI 添加」；
   - 点「测试 SSH 登录」，看到 `Hi <你>! You've successfully authenticated` 就好了。
7. **接入**：点「接入这个远程…」。按钮**不会变灰** —— 没填全时它会直接告诉你差哪一项。
   接入成功后再点「测试连通性」，应该是 `连通性：正常`。

> 页面上那行「当前状态」就是答案：`还没填…` / `还没接入…` / `已接上 … · 12:31 同步过` /
> `上次同步失败：…`。点它旁边的「看详情」看完整信息。

> 完整包**不会**被推上去（太大）。第一次搬家仍然要手动拷一次，见下一节。

---

## 1. 第一次搬家：完整包手动搬

**A 机**

1. 打开「导出同步包…」→ 把「导出完整副本」打开、「导出更新包」关掉 → 导出。
   - 包会落在 `D:\LocallySaveBundles\full\…lsave`；`git status` 里**不该**出现它（可能被忽略）。
2. 把这个 `.lsave` 拷给 B（U 盘 / 网盘 / 聊天软件都行）。

**B 机**

1. 把包放进 B 的 `D:\LocallySaveBundles\full\`（没有 `full` 文件夹就自己建一个）。
2. 命令面板 →「打开同步包并应用…」→ 选中它 → 看一眼报告 → 应用。
3. 设置 → Git 远程 →「当前状态」→「看详情」：应该能看到 `另一台：状态 xxxx`。

到这儿两台机器站在**同一个基准点**上，后面互发更新包才对得上号。

---

## 2. 日常：改完就互相应用

### 只有一边改

1. A 改一篇笔记（改完等 2 秒，或者让内容长度变一下 —— 插件判断"动没动"有 2 秒容差）。
2. A 机点左侧栏第一个图标「立即同步」（或命令面板同名命令）—— 它会导出更新包、推上去、顺手拉一遍
   （只导出、不推拉的场景才用「导出同步包…」；「让对面和我一致」是强制单向推，日常不用）。
3. B 机等 5 分钟，或者也点「立即同步」/命令「与 git 远程同步一次」。
   - 方向是**双向**时，拉下来的更新包会被**自动应用**（不会删东西、不会覆盖本地改动的那种）。
   - 状态栏会变成：`已推拉 12:31 · 对方：一致`（前半句是 git 推拉结果，后半句才是内容一致）。
4. 两边打开同一篇笔记，内容应该一样；再对一下「同步包更新记录…」顶部的
   `我现在：状态 xxxx` —— **两边必须完全相同**。

> 「立即同步」是手动的。想完全不用点：设置 → 自动留包 → 打开「留更新包」+ 选一个间隔（比如 5 分钟）。
> 之后 A 改完，到点自动导出、下一个 30 秒节拍自动推；B 到点自动拉、自动应用。

### 两边各改一处（不该撞号）

1. A 改一篇（`a.md`），点「立即同步」→ A 的更新包是**下一个世代**（比如第 101 代）。
2. B 改另一篇（`b.md`），点「立即同步」→ B 会**先拉到 A 的 101**，再发号，
   所以 B 的包是**第 102 代**，不会也出现一个 101。
3. A 再点「立即同步」→ 拉 B 的 102 并应用（两边的改动都留下）。
4. 对账：两边「同步包更新记录」顶部的世代号和状态编号一致；
   货架里 A 的包是 101、B 的包是 102，**没有两份同代包**。

> 如果以前已经各自导出过两个同为 101 的包（旧版本留下的），先手动删掉其中一份，
> 之后按新流程发号就不会再撞。

### 改名 / 移动文件夹

1. A 把一个大文件夹改个名（或挪个位置），点「立即同步」。
2. A 的更新包应该**很小**（几 KB 的头部；负载为 0），不是文件夹那么大 ——
   「同步包更新记录」/导出结果里会写「N 处移动」；包里版本是 v2。
3. B 点「立即同步」（或等自动拉取）→ 文件直接改名过去，内容不重传；
   两边「我现在：状态 xxxx」一致。
4. 再在移过的文件夹里**改一个文件**、**删一个文件**，各同步一次：
   改过的那个才带内容，删掉的会同时点名旧路径和新路径（B 那边新路径也删掉）。

> 带移动操作的包是 **v2**：另一台必须也是 0.15.1 及以上（旧插件会明确拒绝，不会把移动误当删除）。
> 源文件被本地改过、或目标路径已存在时，应用会先拒绝并提示，不会做半套。

### 两边都改了同一篇（撞车）

插件**不会**像 Remotely Save 那样每个文件猜着合 —— 它会停下来：

- B 的状态栏出现 `对方：不同步`；自动应用会跳过那个包（它要覆盖 B 的改动）。
- 这时**由你定以谁为准**，两个按钮（命令面板里同名）：
  - 在 B 点「让我和对面一致（拉下来）」→ B 变成 A 那一份；B 原来改的那份进回收目录
    （`.trash/locally-save`，捞得回来），B 的状态编号跟 A 一致。
  - 或者让 B 以自己为准：先点一次「立即同步」把 B 的改动导出推上去，再到 A 点「让我和对面一致（拉下来）」。
- 选完方向、同步一次，两边状态编号就一致了。

**为什么不做"每文件各取一半"**：那样两边各留一份自己的版本，状态编号永远对不上，
下一次谁也不知道该信谁 —— 这正是严格包模型要避免的。以谁为准由你点一下，结果**完全确定**。

### 删除

A 删掉一篇笔记 → 点「立即同步」（导出并推上去）。
B 自动应用**不会**替它删东西（删除是唯一不可逆的动作），会弹一句提示说收到一个包但没应用；
在 B 点「让我和对面一致（拉下来）」，或在「打开同步包并应用…」里选那个包看一眼再应用，删除就过去了。

---

## 3. 对账：两边到底一不一样

两台机器都做：

1. 状态栏：`已推拉 12:31 · 对方：一致`（有对方状态文件之后才有后半句）；
   刚应用完、对方还没上报时写 `对方：待上报`，不是"不同步"；
2. 设置 → Git 远程 →「当前状态」→「看详情」：`另一台：状态一致 · 站在第 N 代 · 最后应用 …`；
3. 命令「同步包更新记录…」：顶部 `我现在：状态 xxxx`，两边相同；
4. 想再确认货架：
   ```powershell
   cd D:\LocallySaveBundles
   git ls-files        # 只有 changes/… 与 .lsave-peers/…；不该有 full/…
   git log --oneline -5
   ```

---

## 4. 应该看到什么（验收）

- 打开 git 后，货架里只有 `changes/`（更新包）和 `.lsave-peers/`（每台机器的小状态），
  **没有** `full/*.lsave`（完整包留在本机）；
- 一边改、另一边在 5 分钟内自动收到并应用（安全的那类），状态栏 `对方：一致`；
  点状态栏或在命令面板搜「查看各台电脑同步状态…」能看到每台状态编号与最后上报时间；
- 两边都改同一篇时：自动应用**不动手**，状态栏 `对方：不同步`，点一下「让我和对面一致」后就一致；
- 删除：不会自动发生，点一下方向按钮才过去；
- 断开网络：状态栏显示 `同步失败 12:31`，不刷屏；恢复后 2–10 分钟自动重试。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| 「还没接上 git」 | 设置 → Git 远程 →「接入这个远程…」 |
| `Permission denied (publickey)` | 这台机器的公钥没加到 GitHub；按第 0 步第 3 条 |
| `git 失败` 一直是 | 设置 → Git 远程 →「当前状态」→「看详情」看远程地址；凭据先在终端 `git -C <货架> pull` 一次（插件不存 token） |
| 对方一直「不同步」 | 两边都点一次「与 git 远程同步一次」；再对一下两边的状态编号 |
| 导出后货架没变化 | 点「立即同步」；它默认会导包（有基准导更新包、没基准导完整包） |
| 包太大推不上去 | 更新包超过 50 MB 会失败；先换一份新的完整副本当基准（设置里「攒大了提醒立新基准」） |
| 想撤销「以对面为准」 | 本机被换掉的文件在 `.trash/locally-save/` 里，捞回来即可 |

---

## 测完告诉我

1. 两边状态编号是否一致（第 3 步）；
2. 状态栏的 `对方：一致` / `对方：不同步` 是否符合预期；
3. 两边都改同一篇时，点「让我和对面一致」的结果对不对；
4. 哪一步的提示看不懂。

这三步过了，0.15.0 的 git 货架就可以当日常同步用了。
