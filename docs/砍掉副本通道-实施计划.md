# 砍掉副本通道 —— 实施计划

决定：**移除「同步到本地副本」整条通道，插件收敛为纯同步包通道（完整包 + 更新包）。**
理由见 `docs/本地副本同步-分析与优化.md` 与结论：共用目录方向由 Remotely Save + WebDAV/坚果云这类成熟方案覆盖，
我们那条通道是它的弱化实现（mtime 判据、每台机器私有基准、不认多写入者、没有状态编号），
而且两条通道各自实现了一遍"基准 / 冲突 / 回收 / 删除传播"，分叉已经在产生维护税。

---

## 一、保留与删除

### 留下（包通道的主干，一行不动）
`bundle/format.ts`、`baseline.ts`、`export.ts`、`apply.ts`、`log.ts`、`manage.ts`、`size-warn.ts`、
`sync/state-id.ts`、`sync/hash-cache.ts`、`sync/exclude.ts`、`sync/disk.ts`（按需瘦身）、
`ui/*` 里与包有关的部分（bundle-modal / bundle-list / manage-modal / log-modal / reset-baseline-modal /
drop-watch / drop / protocol / associate* / help-modal）。

### `sync/diff.ts` **不删**：`bundle/apply.ts` 的 `normal` 档就走它
`planSync` / `sameRecord` / `dirsContainingFiles` 仍被 `apply.ts` 使用 —— 副本通道没了，但三方比对引擎是包应用的底座。
`test/diff.test.ts` 整套保留。

### 删除
| 对象 | 说明 |
|---|---|
| `sync/runner.ts` | `runSync` / `removeFromTarget` / `SyncHost` / `SyncOutcome` / `assertNotNested` 全部随通道消失 |
| `sync/execute.ts` | 只有副本通道在用它执行 `executePlan` |
| `sync/summary.ts` | `LastSyncRecord` 这一套是"上次同步干了什么"，状态栏改读最后一条更新记录 |
| `ui/sync-modal.ts` | 换成"导出预览"（见下） |
| `test/sync.test.ts` | 整个文件随通道删除；其中"包放在副本目录里不会被同步回仓库"一类用例迁进 `test/bundle.test.ts` |
| `state.targets` / `state.lastSync` | 状态文件字段删除（老状态文件里的留着不读） |
| 设置 `targetDir` / `syncDirection` | 见"设置迁移" |
| `bundle-modal` 的「应用后顺便同步到副本」 | 连带 `alsoSyncCopy`、`removeFromTarget` 调用 |
| 命令 `upload-to-copy` / `download-from-copy` | **保留一版**：仍注册 ID，回调只弹一条通知指路（导出包 / 应用包），下一版再删 |

### 搬家（不改行为，只为能删 runner.ts）
- `excludePatterns()` → `sync/exclude.ts`
- `VAULT_TRASH_DIR`（`.trash`）→ 新建 `sync/vault.ts`（连同这两个的说明）
- import 点：`bundle/export.ts`、`bundle/apply.ts`

## 二、命令与设置的处置（稳定接口的规矩）

`AGENTS.md`：**命令 ID 不许改名、设置字段名不许改名；删设置项可以，但语义不能悄悄变、该留的能力不能删。**

### 命令（ID 全部保留）
| ID | 原来 | 现在 |
|---|---|---|
| `sync-now` | 立即同步到副本 | **立即留包**：按两个「自动留包」开关立即留一次；都没开时提示去「导出同步包…」 |
| `sync-preview` | 预览同步 | **预览这次会留什么包**：列出将装进更新包的文件与删除清单，只读不写 |
| `upload-to-copy` | 仅上传到副本 | 保留 ID，回调改为通知：「副本通道已移除，用『导出同步包…』」 |
| `download-from-copy` | 仅从副本拉取 | 保留 ID，回调改为通知：「副本通道已移除，用『打开同步包并应用…』」 |
| 其余（export/apply/manage/bundle-log/toggle-enabled） | 不变 | 不变 |

### 设置
| 字段 | 处置 |
|---|---|
| `targetDir` | **删**。迁移：旧的 `bundleDir` 为空且旧 `targetDir` 非空 → `bundleDir = <旧 targetDir>/.lsave/bundles`（包留在原地，用户不用重新找） |
| `syncDirection` | **删**（只被副本通道用） |
| `propagateDeletions` / `conflictStrategy` / `deletedToTrash` | **留**：`bundle/apply.ts` 的 `normal` 档拿它们当默认值。文案改成"应用同步包时……"，从"同步目标"组挪进"应用同步包"组 |
| `excludePatterns` | **留**（导出与应用的扫描都用），文案改成"不进包的文件" |
| `bundleDir` | **从"可留空"变成必填**：没有 targetDir 兜底了。空着时导出/应用按钮禁用并提示去填 |
| `syncOnStartup` / `autoSyncInterval` / `syncAfterSaveDelay` | **留（字段名不变），语义改为"自动留包的时机"**。两个「自动留包」开关都没开时，触发了也什么都不做（只记日志），不弹错 |
| `autoExportChanges` / `autoExportFull` / `bundleSizeWarnLimit` / `bundleVerify` / `dropBundleToApply` | 留，文案去掉"同步后"的说法 |
| `ribbonSyncIcon` | 留，文案改成"立即留包"（图标动作＝`sync-now`） |
| `ribbonExportIcon` / `ribbonApplyIcon` / `showStatusBar` / `enabled` / `logLevel` | 留，文案微调 |

### 状态文件
- `state.targets`（每目标的基准）删除 → `loadState` 不再读，`saveState` 不再写
- `state.lastSync`（`LastSyncRecord`）删除
- 状态栏平时那句话改读**最后一条 `bundleLog`**（`describeLogEntry` / `describeBundlePosition`），
  没有记录时显示"尚未留包"
- `state.copyId` 留着（包头部/排查用），`lineage` / `generation` / `bundle` / `hashes` / `stateId` / `pendingReturn` / `bundleLog` 都不动

## 三、新东西：导出预览（`sync-preview` 的新用途）

现在没有"先看看这次会导什么"的地方 —— 导出弹窗是选完就写。
所以把 `ui/sync-modal.ts` 换成 `ui/export-preview-modal.ts`：

- 内容：会装进**更新包**的文件列表（path、变更类型）、删除清单、文件数、估算大小；
- 数据来源：`bundle/export.ts` 里抽出 `planBundleExport()`（**纯计算、不写盘**），`exportBundle` 内部改用它 —— 一份逻辑两处用，不复制粘贴；
- 底部按钮：「导出更新包」（打开导出对话框或直接导）与「取消」。

## 四、自动留包的触发链路（原来挂在同步之后）

现状：`syncNow()` 先跑 `runSync`，成功后才 `autoExportBundles(outcome)` —— 没有目标文件夹就一步都跑不了。

改成：
```
tick()（启动 / 定时 / 保存后）
   └─ 有「自动留包」开关开着？ → exportBundlesNow()
        ├─ 扫一次仓库（scanTree）
        ├─ 按 plannedExportModes() 先完整、后更新
        ├─ exportBundle({ inventory })   ← 复用同一次扫描
        └─ 状态栏/通知 + offerBaselineReset()
```
- 插件级串行锁从"同步锁"改成"留包锁"（`main.ts` 的 `syncing` → `bundleBusy`），
  `runSync` 方法改名为 `runBundleExport`（内部 API，不是命令 ID）；
- 应用那边已有自己的模块级锁（`apply.ts` 的 `applying`），保持；
- `ui/actions.ts` 的 `syncNow` / `autoExportBundles` 合并成 `exportBundlesNow(plugin, { modes })`。

## 五、实施顺序（每步结束都要 `npm test` 绿）

1. **搬家**：`excludePatterns` → `sync/exclude.ts`；新建 `sync/vault.ts` 放 `VAULT_TRASH_DIR`；改 import。

3. **状态**：`state.ts` 去掉 `targets` / `lastSync`；删 `sync/summary.ts`；状态栏改读 `bundleLog`。
4. **接线**：`main.ts`（去掉 SyncHost 实现与 runSync，改留包触发）、`ui/actions.ts`、`commands/index.ts`、`ui/bundle-modal.ts`（去掉 alsoSyncCopy）。
5. **删代码**：`sync/runner.ts`、`sync/execute.ts`、`ui/sync-modal.ts`（换成 export-preview-modal）、`test/sync.test.ts`。
6. **测试**：改 `test/commands.test.ts`（命令表现状 + 锁）、迁移用例（旧 data.json → bundleDir）、"没设包目录时的行为"；跑 `npm test` + `npm run build` + `npm run lint`。
7. **文档**：`README.md`（删副本章节、加"为什么砍掉"与迁移说明）、`AGENTS.md`（删副本通道硬约束，补一条通道的新约束），`manifest.json` / `versions.json` → 0.8.0。

## 六、验收标准

- `npm test` 全绿（`test/diff.test.ts` 的比对矩阵一条不少 —— 它是包应用的底座）；
- 老 `data.json` 升级后：包目录自动落到原来的 `<targetDir>/.lsave/bundles`，其余设置不变；
- 只设包目录、不开任何自动触发时：手动导出/应用/管理/更新记录全部可用；
- 打开「自动留更新包」+ 定时留包：不用目标文件夹也能跑，状态栏显示"已留更新包"；
- 四个命令 ID 仍在（`upload-to-copy` / `download-from-copy` 只弹指路通知）；
- `grep -r "runSync\|targetDir\|syncDirection" src/` 只剩迁移代码里的旧字段名读取。
